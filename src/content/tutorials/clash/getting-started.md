Clash 是一类以规则分流为核心的代理客户端的统称。原版 Clash 内核已于 2023 年底停止维护并删除仓库，目前主流的选择是基于 Mihomo（原 Clash Meta）内核的图形客户端，其中桌面端以 Clash Verge 系列使用最广。入门只需四步：安装客户端 → 导入订阅 → 选择节点 → 开启系统代理，本文按这个顺序完整走一遍。

## 核心要点

- 原版 Clash 已停更，现在应选择 **Mihomo 内核**的衍生客户端（如 Clash Verge 系列）；
- 务必从 **GitHub Releases 等可信渠道**下载，搜索引擎里排前的“官网”不少是仿冒站；
- 上手流程固定：**安装 → 导入订阅 → 选节点 → 开系统代理**，每一步都可验证；
- 日常使用选**规则模式**，全局模式只用于排查问题；
- **TUN 模式**用于接管不走系统代理的程序，普通浏览场景不必开启。

## Clash 是什么？现在应该装哪个？

Clash 最初是一个开源代理内核，凭借「一份配置 + 规则分流」的设计成为机场订阅的事实标准。2023 年 11 月，原作者删除仓库停止开发，常用的图形客户端 Clash for Windows 也随之停更。此后社区由 Clash Meta 分支延续开发，并更名为 **Mihomo**——这就是今天所有活跃 Clash 系客户端的内核。

对普通用户来说，结论很简单：

- **Windows / macOS / Linux**：选择 Clash Verge 系列（社区维护的活跃分支）；
- **Android**：选择基于 Mihomo 内核的 Clash 客户端；
- 机场提供的「Clash 订阅」在这些客户端上通用，无需做任何转换。

关于 Mihomo 生态的更多内容可见 [Mihomo 专题](/tutorials/mihomo/)。下载时认准项目的 **GitHub Releases 页面**：通过搜索引擎广告或网盘流传的安装包被植入恶意程序的案例屡见不鲜，客户端掌握你的全部流量，来源必须干净。

## 如何从安装走到成功连接？

以下流程适用于各桌面客户端，界面措辞可能略有差异，但逻辑一致。开始前请准备好机场的**订阅链接**——登录机场官网的用户中心即可复制，还没有订阅的话可先看[新手怎么选机场](/airport/beginners/)。

1. **下载安装**：在项目 GitHub Releases 页面选择对应系统与架构的安装包，安装后启动；
2. **复制订阅链接**：从机场用户中心复制 Clash 订阅地址（部分机场提供「一键导入」按钮，效果相同）；
3. **导入订阅**：打开客户端的「订阅 / 配置」页面，粘贴链接并确认下载；
4. **确认导入成功**：订阅条目出现且无报错，「代理」页面能看到机场的节点与策略组；
5. **选择节点**：在策略组中先执行一次延迟测试，选一个延迟正常的就近节点（如香港、日本）；
6. **开启系统代理**：回到主界面打开「系统代理」开关；
7. **验证连通**：用浏览器访问一个境外网站，能正常打开即配置完成；
8. **养成更新习惯**：机场会不定期更换服务器，之后定期或在连接异常时手动更新订阅。

两个常见卡点各有专文：订阅下载报错见[Clash 订阅更新失败怎么办](/troubleshooting/clash-subscription-update-failed/)；节点列表正常但全部测速超时，见[节点全部超时怎么办](/troubleshooting/all-nodes-timeout/)。对节点、订阅这些概念还不清楚的读者，建议先补一篇[什么是代理节点](/nodes/what-is-a-proxy-node/)。

## 规则模式和全局模式有什么区别？

Clash 的分流模式是它区别于简单代理工具的核心，共三种：

| 模式 | 行为 | 适用场景 |
| --- | --- | --- |
| 规则（Rule） | 按规则自动分流：境外走代理、境内直连 | 日常使用的默认选择 |
| 全局（Global） | 所有流量都经当前节点转发 | 排查问题、特殊需求时临时使用 |
| 直连（Direct） | 所有流量不走代理 | 临时停用代理而不关闭客户端 |

规则模式的价值在于「无感」：访问国内网站不绕路、不耗流量，访问境外网站自动走节点，一次配置长期省心。机场订阅一般都内置了维护好的规则集，新手无需自己编写规则。全局模式则是排障利器——当你怀疑“是分流规则没匹配到，还是节点根本不通”时，切到全局一测便知。

## TUN 模式是什么？什么时候需要开？

「系统代理」并不是强制的：它只是告诉操作系统“建议走这个代理”，浏览器等守规矩的程序会遵守，但**很多命令行工具、游戏和部分桌面应用不读系统代理设置**，它们的流量会绕过 Clash 直接出去。

TUN 模式的解决思路是在系统里创建一块**虚拟网卡**，在网络层接管设备的全部流量，无论程序是否配合都会被纳入分流。什么时候开：

- 需要代理不吃系统代理的程序（终端命令、游戏、某些开发工具）时开启；
- 日常仅浏览网页、看视频，用系统代理即可，不必开。

注意事项：开启 TUN 通常需要管理员权限或安装系统服务；它与其他 VPN 类软件同时运行容易冲突，建议同一时间只让一个工具接管网络。

## 连接失败时先检查什么？

遇到问题不要急着重装，按共性环节的顺序检查，命中率最高：

1. 订阅是否导入成功、节点数量是否正常；
2. 系统代理开关是否打开、模式是否误切到直连；
3. 换一个节点或策略组再测，排除单节点故障；
4. 是否有其他代理软件同时运行造成端口冲突。

如果你在 Windows 上更习惯轻量工具，也可以试试另一条路线：[v2rayN 入门指南](/tutorials/v2rayn/getting-started/)，两者可以并存但同一时间只运行一个。

## 总结

Clash 入门的关键是理清版本脉络与固定流程：认准 Mihomo 内核的活跃客户端，从 GitHub Releases 下载，然后按「导入订阅 → 选节点 → 开系统代理 → 验证」四步走完第一次连接。日常保持规则模式，需要接管全部流量时再开 TUN。剩下的经验——更新订阅、排查超时、优化分流——都会在使用中自然积累。
