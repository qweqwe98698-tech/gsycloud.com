代理节点是一台部署在其他网络区域、替你转发流量的远程服务器：你的设备把请求交给节点，节点代替你访问目标网站，再把结果传回来。订阅是批量获取节点列表的更新地址，客户端则是安装在你设备上、负责管理节点和分流规则的软件。三者配合，才构成一次完整的代理连接。

## 核心要点

- 节点的本质是**远程转发服务器**，它决定了你的出口 IP 与网络路径；
- 订阅是**动态更新的节点清单**，机场更换服务器后靠它同步最新节点；
- 客户端是**本地调度中心**，负责选节点、做分流、开启系统代理；
- 节点名称中的**地区、线路标注、倍率**都有明确含义，读懂它们才能选对节点；
- **延迟低不等于速度快**，两者衡量的是不同指标。

## 代理节点到底是什么？

可以把代理节点想象成一座**跨境快递中转仓**。你要寄一件目的地无法直达的包裹，于是先把它寄到中转仓，由中转仓以自己的名义发往目的地，回件也原路转交给你。在整个过程中，收件方看到的发货地址是中转仓，而不是你家。

对应到网络上：节点就是那座中转仓。你访问一个网站时，流量先加密送到节点服务器，节点解密后代替你去访问目标，网站看到的访问者是节点的 IP。因此节点所在的地区，直接决定了你在互联网上呈现的“位置”。

技术上，一个节点通常由四要素构成：**服务器地址（IP 或域名）、端口、协议类型、身份凭证（密码或 UUID）**。协议规定了你的设备与节点之间如何加密通信，常见的有 VLESS、VMess、Trojan、Shadowsocks 等，它们的差异可参考 [VLESS 和 VMess 有什么区别](/protocols/vless-vs-vmess/)。

## 节点、订阅、客户端是什么关系？

三者的关系可以用一个点外卖的类比来理解：**节点是一家家餐厅，订阅是不断更新的餐厅名录，客户端是帮你下单的外卖 App**。餐厅会开张也会倒闭，名录负责保持最新，而你始终只需要操作那一个 App。

| 角色 | 类比 | 作用 | 常见形态 |
| --- | --- | --- | --- |
| 节点 | 餐厅 | 实际转发流量的服务器 | IP + 端口 + 协议 + 凭证 |
| 订阅 | 餐厅名录 | 批量下发并更新节点列表 | 一条 https 链接 |
| 客户端 | 外卖 App | 管理节点、执行分流、开启代理 | Clash Verge、Shadowrocket、v2rayN 等 |

完整的使用流程是这样的：

1. 在机场（节点服务商）购买套餐，获得一条**订阅链接**（选购思路见[新手怎么选机场](/airport/beginners/)）；
2. 把订阅链接导入客户端，客户端自动解析出全部节点；
3. 客户端定期**更新订阅**，机场增删服务器时节点列表随之刷新；
4. 你在客户端里选择节点、开启系统代理，开始使用。

理解这个链条对排障非常重要：节点失效时问题可能出在订阅没更新，也可能出在客户端配置，而不一定是服务器坏了。客户端的具体操作可以从 [Clash 入门指南](/tutorials/clash/getting-started/)开始学习。

## 节点名称怎么读？

打开节点列表，你会看到类似「香港 03 | IPLC | 2x」这样的名称。它一般由**地区 + 编号 + 线路标注 + 倍率**组成，每一段都有含义：

| 标注 | 含义 | 对使用的影响 |
| --- | --- | --- |
| 香港 / 日本 / 美国等 | 服务器出口所在地区 | 决定访问延迟与可解锁的区域内容 |
| IPLC / IEPL / 专线 | 不经公网出口的专用线路 | 晚高峰稳定，通常倍率更高 |
| 中转 / 隧道 | 流量先经境内服务器转发 | 价格与稳定性的折中 |
| 直连 | 设备直接连境外服务器 | 成本低，晚高峰波动明显 |
| 0.5x / 2x / 3x | 流量计费倍率 | 1GB 流量按对应倍数扣除 |
| 原生 / 家宽 | 本地注册 IP 或住宅 IP | 对流媒体解锁、风控敏感场景更友好 |

其中线路标注对体验影响最大：专线与公网线路的差异可以读 [IPLC 是什么](/network/what-is-iplc/)，原生 IP 的价值见[什么是原生 IP](/network/native-ip/)。选节点时先看地区是否符合需求，再权衡线路等级与倍率成本。

## 延迟和速度是一回事吗？

不是，这是新手最常混淆的两个概念：

- **延迟（Latency）**以毫秒计，衡量数据一来一回需要多久，好比快递客服响应快不快；
- **速度（带宽）**以 Mbps 计，衡量单位时间能传多少数据，好比货车一次能拉多少货。

客户端里的“测延迟”通常只测一次轻量请求的往返时间，能反映节点是否连通、路径是否绕路，但**不代表下载速度**。一个延迟 60ms 的节点可能因为带宽拥挤而看视频卡顿；一个延迟 180ms 的美国节点反而可能跑满你的宽带。日常网页浏览对延迟不敏感，游戏和视频会议才需要斤斤计较。如果节点延迟长期偏高，排查思路见[节点延迟高怎么办](/troubleshooting/high-latency/)。

## 新手应该从哪里开始？

理解了节点、订阅、客户端的关系后，建议按这个顺序上手：

1. 选择一家口碑可查的机场获取订阅，避免一开始就踩坑；
2. 如果只想先体验流程，可以用免费节点练手，但注意它的限制与风险，详见[免费节点怎么使用](/nodes/free-nodes-guide/)；
3. 桌面端从 Clash 系客户端入门，跟着教程完成第一次连接；
4. 遇到连不上、速度慢等问题时，按故障排查文章的顺序定位，而不是盲目换节点。

## 总结

代理节点是替你转发流量的远程服务器，订阅负责把最新的节点清单同步到客户端，客户端则在本地完成选择节点与分流的全部工作。读懂节点名称里的地区、线路与倍率标注，分清延迟与速度的区别，你就掌握了选择和使用节点的基本功。剩下的，就是在实际使用中把这套知识用于选购套餐与排查故障。
